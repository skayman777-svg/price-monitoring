Мониторинг цен: проект на Python

Небольшой рабочий проект: обходит каталог интернет-магазина, хранит историю снимков, сравнивает два последних и собирает отчёт в Excel и короткую сводку для Telegram.

Проверено на тестовом магазине. Магазин «ТехноДом» вымышленный, он запускается на вашем компьютере вместе с проектом (mock_shop/). Реальные сайты не обрабатывались, товары и цены придуманы.

Быстрый запуск

pip install -r requirements.txt
python run.py

Что произойдёт: поднимется тестовый магазин, будет снят снимок №1, в магазине изменятся цены, наличие и ассортимент, будет снят снимок №2, затем сравнение, отчёт и сводка. В конце проверка сбоя: раздел недоступен, снимок помечается неполным и в сравнении не участвует.

Результат в папке out/: price_report.xlsx (отчёт), prices.db (история снимков, SQLite), run.log (журнал).

Тесты (31 проверка, без внешних библиотек): python -m unittest discover -s tests -t .

Временный ответ 503 на одной странице: парсер повторил запрос и получил страницу. Полная недоступность раздела: снимок сохранён как неполный, отчёт не строится на неполных данных.

Как подключить свой сайт

  1. Скопировать config.json, указать base_url и разделы каталога.
  2. Подогнать селекторы в monitor/parse.py под разметку сайта: карточка, название, цена, старая цена, наличие, ссылка «следующая страница».
  3. Запускать по расписанию (cron или планировщик заданий Windows): python -m monitor run --config my.json --db out/prices.db --out out/report.xlsx

Первый запуск делает снимок №1, со второго есть что сравнивать. Код выхода 1 означает неполный снимок (удобно для уведомления о сбое). Отдельные команды: crawl (только снимок) и report (только отчёт). Отправка сводки в Telegram: флаг --send и переменные окружения TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID.

Что умеет

  • Аккуратный сбор: честный User-Agent (подмены нет), robots.txt (Disallow и Crawl-delay), пауза между запросами, таймауты, повторные попытки с записью в журнал.
  • Разбор «живой» разметки: неразрывные пробелы в ценах, «от 8 990 ₽», «Цена по запросу», зачёркнутая цена, карточка без цены, баннеры и рекомендации с ценами не попадают в данные.
  • Хранение в SQLite, деньги в копейках (без ошибок округления).
  • Защита от ложных тревог: не загрузился раздел, каталог пуст или товаров стало меньше половины, и такой снимок не участвует в сравнении.
  • Сравнение: снижение и рост цены, новые, пропавшие, снова в наличии, нет в наличии.
  • Отчёт Excel: сводка с графиком, список изменений с цветами и фильтрами, полный прайс.
  • Сводка для мессенджера с порогом по проценту изменения цены.

Ограничения

  • Проект проверен только на тестовом магазине. Каждый реальный сайт требует настройки селекторов и проверки.
  • Если цены на сайте подгружаются скриптами, нужен сбор через браузер (Playwright) либо официальный API или выгрузка. Это отдельная оценка.
  • Защиту от ботов (капчи, Cloudflare и подобное) проект не обходит, обход не гарантируется. Перед работой с чужим сайтом нужно изучить условия использования и robots.txt; где есть официальный API или фид, лучше брать данные из них.
  • Отправка в Telegram написана, но на настоящем боте не запускалась.
  • В отчёте значения, а не формулы: файл одинаково открывается в любых программах.

Структура

run.py             сквозной тестовый запуск
config.json         сайт, разделы, задержки, порог уведомлений
monitor/            fetch (загрузка), parse (разбор), crawl (обход), store (SQLite),
                    diff (сравнение), report (Excel), notify (сводка), cli
mock_shop/          тестовый магазин для прогона и тестов
tests/              unittest: разбор цен и карточек, сравнение, сбои, robots.txt, отчёт
